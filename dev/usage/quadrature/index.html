Assembly

Everything this package assembles comes out of one data structure. A SplineQuadrature tabulates a basis and its derivatives at the Gauß-Legendre points of every cell, and every matrix of the form

\[A_{kl} = \int_\Omega f(x) \, D^a \phi_k \, D^b \phi_l \, \mathrm{d}x\]

is then a single weighted contraction of that table,

\[A = \Phi_a \, \mathrm{diag}(f \odot w) \, \Phi_b^{\mathsf T} .\]

using SimpleSplines
using LinearAlgebra
using SparseArrays

Construction

SplineQuadrature(basis; nq = quadrature_order(degree(basis)), dmax = 3)

Any of the three bases serves. What differs between them is which functions are nonzero on a cell (local_indices) and which representation the mass matrix takes (mass_operator); the contractions are identical.

b = BSplineBasis(UniformMesh(16, 0 .. 2π), 3, Periodic())
q = SplineQuadrature(b)
nbasis(q), degree(q), ncells(q), length(quadrature_nodes(q))
(16, 3, 16, 80)
  • nq is the number of quadrature points per cell. The default, quadrature_order(p) = ⌈3p/2⌉, integrates degree $3p-1$ exactly — see Choosing nq below.
  • dmax is the highest derivative order tabulated. Three is what a third-order operator needs after one integration by parts. Asking basis_values for more is an error naming the fix.
quadrature_order.(0:5)
6-element Vector{Int64}:

try
    basis_values(SplineQuadrature(b; dmax = 1), 2)

The table

callreturns
quadrature_nodes(q)the n*nq global points, in cell order
quadrature_weights(q)the matching weights, scaled by the cell widths, so sum(w) == L
basis_values(q, d = 0)the sparse N × n*nq table $\Phi_d[i,r] = D^d\phi_i(x_r)$
basis(q)the basis
mass_operator(q)the MassOperator
nbasis, degree, order, ncells, domainlength, meshwidth, eltypeforwarded to the basis
sum(quadrature_weights(q)) ≈ domainlength(b)
true

The global index of the r-th point of cell k is (k-1)*nq + r, so a hand-written assembly loop reads

Φ = basis_values(q, 0)
w = quadrature_weights(q)
nq = length(quadrature_nodes(q)) ÷ ncells(q)
total = sum(w[(k - 1) * nq + r] * Φ[i, (k - 1) * nq + r]
for k in 1:ncells(q) for i in local_indices(basis(q), k) for r in 1:nq)
total ≈ domainlength(b)              # ∑ᵢ ∫ φᵢ = ∫ 1 = L
true

The table is sparse, and that is the point

A basis function is supported on p+1 cells, so only (p+1)*nq of the n*nq entries in its row can be nonzero, and only those are stored.

nnz(Φ), ncells(q) * (degree(q) + 1) * nq, nnz(Φ) / length(Φ)
(320, 320, 0.25)

Storing $\Phi$ densely would make every contraction $\Phi \, \mathrm{diag}(f \odot w) \, \Phi^{\mathsf T}$ cost $O(N^2 n n_q)$ instead of $O(N p^2 n_q)$.

The matrices

callmatrix
mass_matrix(q)$\mathbb{M}_{kl} = \int \phi_k \phi_l$
stiffness_matrix(q)$\mathbb{K}_{kl} = \int \phi_k' \phi_l'$
derivative_matrix(q)$S_{kl} = \int \phi_k \phi_l'$
mixed_matrix(q, a, b)$\int D^a\phi_k \, D^b\phi_l$
weighted_matrix(q, f, a, b)$\int f \, D^a\phi_k \, D^b\phi_l$
basis_integrals(q)the vector $\int \phi_i$

stiffness_matrix and derivative_matrix are mixed_matrix(q, 1, 1) and mixed_matrix(q, 0, 1) — the same objects, not merely equal ones:

stiffness_matrix(q) === mixed_matrix(q, 1, 1),
derivative_matrix(q) === mixed_matrix(q, 0, 1)
(true, true)
`mixed_matrix` is memoised, and returns the cached object

These are constants of the discretisation and are asked for inside every Newton iteration of every step of a downstream integrator, so each (a, b) is assembled once and kept. The consequence is that the result is shared: mutating it changes what every later call returns. Take a copy before writing into one.

mixed_matrix(q, 0, 2) === mixed_matrix(q, 0, 2)
true

The same holds for mass_matrix and basis_integrals, which are assembled when the quadrature is built and returned by reference.

Structural identities

On a periodic mesh derivative_matrix is already antisymmetric, with no skew-symmetrisation needed, because integration by parts over a torus leaves no boundary term:

S = derivative_matrix(q)
maximum(abs, S + S')
6.661338147750939e-16

The stiffness matrix is symmetric positive semi-definite with the constants in its kernel:

K = stiffness_matrix(q)
(maximum(abs, K - K'),
    minimum(eigvals(Symmetric(Matrix(K)))),
    maximum(abs, K * ones(nbasis(q))))
(1.1102230246251565e-16, 1.1657341758564144e-15, 8.881784197001252e-16)

And integration by parts holds between the mixed matrices, which is what lets a third-order operator be carried by a $\mathcal{C}^2$ cubic basis:

maximum(abs, mixed_matrix(q, 1, 2) + mixed_matrix(q, 0, 3))
2.955968803064479e-14

A variable coefficient costs no more than a constant one

weighted_matrix takes either a function of the coordinate or a vector already sampled at quadrature_nodes — the second form is what a coefficient that is itself a spline expansion becomes, and it avoids resampling a field already in hand.

A1 = weighted_matrix(q, sin, 0, 1)
A2 = weighted_matrix(q, sin.(quadrature_nodes(q)), 0, 1)
A1 == A2, maximum(abs, weighted_matrix(q, one, 0, 0) - mass_matrix(q))
(true, 1.3877787807814457e-17)

Its element type is the promotion of the quadrature's with the sample's, so a complex coefficient field gives a complex matrix — unlike mixed_matrix, which carries no weight and is always eltype(q):

eltype(weighted_matrix(q, cis, 0, 0)), eltype(mixed_matrix(q, 0, 0))
(ComplexF64, Float64)
`weighted_matrix` allocates on every call, and there is no in-place form

It is the one assembly that cannot be memoised — it depends on the field, so a time integrator asks for a different one inside every Newton iteration. Measured at $N = 128$, $p = 3$, $n_q = 5$ that is about 260 kB per call, most of it the freshly built SparseMatrixCSC result rather than a temporary. weighted_matrix! does not exist yet; a caller in that position should hold the matrix across steps and accept the allocation, or assemble the contraction by hand against a cached sparsity pattern.

Projection

l2_projection(q, f)            # f a function, or a vector sampled at quadrature_nodes(q)
l2_projection!(û, q, f)        # in place
l2_projection!(s::Spline, q, f)

$\hat{u} = \mathbb{M}^{-1} \int_\Omega f \phi_i$, which is the best approximation of f in the space in the $L^2$ norm.

û = l2_projection(q, sin)
maximum(abs(evaluate(b, û, x) - sin(x)) for x in range(0, 2π; length = 401))
3.425863447992228e-5
v̂ = similar(û)
l2_projection!(v̂, q, sin)
v̂ == û
true

The in-place form allocates nothing on every representation but one: the $f \odot w$ product goes into a buffer the quadrature holds, the load vector is formed with mul! straight into û, and both the CirculantMass and the BandedMass solve are themselves allocation-free. The exception is a periodic basis on a non-uniform mesh — the FactorizedMass case — where CHOLMOD has no in-place solve.

fq = sin.(quadrature_nodes(q))
l2_projection!(v̂, q, fq)                       # warm up
@allocated l2_projection!(v̂, q, fq)
0

A sample whose element type is wider than the quadrature's — a complex f — gets its own product rather than being narrowed into that buffer, so the in-place form accepts exactly what the allocating form accepts and merely stops being allocation-free there.

Mass operators

Solves against the mass matrix go through a MassOperator, and which representation is built is decided by the basis, not by the mesh. A uniform mesh is necessary for circulance but not sufficient: a clamped basis on one has $p$ boundary functions at each end that are not translates of anything.

The circulant construction verifies circulance rather than assuming it, to atol = 1e-10 by default. A matrix that is banded but not circulant would still produce plausible numbers through the transform, and the failure would surface much later as a wrong conservation law.

qg = SplineQuadrature(BSplineBasis(GradedMesh(16, 0 .. 2π), 3, Periodic()))
try
    CirculantMass(mass_matrix(qg), nbasis(qg))
catch err
    println(err.msg)
end
the mass matrix is not circulant to within 1.0e-10; a CirculantMass is only valid on a uniform mesh

Choosing nq

An nq-point Gauß-Legendre rule is exact to degree $2n_q - 1$. Three thresholds matter:

what needs to be exactdegreerequires
the mass matrix $\int \phi_k \phi_l$$2p$$n_q \ge p + 1$
the antisymmetry of derivative_matrix, i.e. $\int (\phi_k\phi_l)'$$2p - 1$$n_q \ge p$
a quadratic nonlinearity, $\int u_h u_{h,x} \phi_i$$3p - 1$$n_q \ge \lceil 3p/2 \rceil$, the default

Below the second threshold the antisymmetry does not degrade gracefully — it fails outright, and only on a non-uniform mesh, because a uniform periodic mesh gives circulant assemblies for which it holds at any nq. That is exactly the case where a check run on a uniform mesh confirms the property for the wrong reason:

p = 3
for nq in 2:6
    qu = SplineQuadrature(BSplineBasis(UniformMesh(16, 0 .. 2π), p, Periodic()); nq = nq)
    qr = SplineQuadrature(BSplineBasis(RandomMesh(16, 0 .. 2π), p, Periodic()); nq = nq)
    du = maximum(abs, derivative_matrix(qu) + derivative_matrix(qu)')
    dr = maximum(abs, derivative_matrix(qr) + derivative_matrix(qr)')
    println("nq = ", nq, "   uniform ", rpad(du, 24), "   random ", dr)
end
nq = 2   uniform 2.4147350785597155e-15     random 0.009260061147333064
nq = 3   uniform 8.326672684688674e-16      random 1.061650767297806e-15
nq = 4   uniform 4.996003610813204e-16      random 1.9298800787824347e-15
nq = 5   uniform 6.661338147750939e-16      random 7.916355714075767e-16
nq = 6   uniform 4.440892098500626e-16      random 4.979386229561141e-16

Too coarse an nq makes the mass matrix singular rather than merely inexact, and the constructor says so by name:

try
    SplineQuadrature(BSplineBasis(UniformMesh(8, 0 .. 1), 3); nq = 1)
catch err
    println(err.msg)
end
the mass matrix assembled with nq = 1 points per cell is not usable for a degree-3 basis on 8 cells: the mass matrix is not positive definite; the quadrature is too coarse to resolve the basis. Use nq ≥ 4 for an exact mass matrix, or at least nq ≥ 2

Two traps

One quadrature per thread

A SplineQuadrature carries mutable state behind an otherwise read-only interface: mixed_matrix memoises into a Dict, and l2_projection! forms its $f \odot w$ product in a shared buffer. Neither is synchronised, so one quadrature must not be used from two threads at once. Give each thread its own, or stay with the allocating l2_projection, which forms its own product.

Several results are returned by reference

mass_matrix, basis_integrals, basis_values and every mixed_matrix hand back the quadrature's own storage. copy before mutating.
